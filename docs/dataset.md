# Synthetic dataset

Everything is generated by code -- there is no dataset to download. Run
`python3 main.py generate` (or just `python3 main.py`, which generates it
automatically if missing) to produce it locally.

## Image format

- 640x480 pixels, grayscale, 8-bit PNG
- Organized on disk as `dataset/images/<category>/<index>_<category>.png`
- Ground truth in `dataset/labels.csv`

## Category breakdown

Default counts (in `config.py`), 2,000 images total:

| Category | Count | Description |
|---|---|---|
| `normal` | 1,500 | Circular Gaussian (`sigma_x == sigma_y`), no rotation, small center jitter, light Gaussian noise. |
| `tilted` | 75 | Elliptical Gaussian (`sigma_major != sigma_minor` by >=10px), rotated 10-170 degrees. |
| `noisy` | 250 | Beam (circular or elliptical) plus heavy Gaussian noise, a random background gradient, and hot pixels. |
| `background` | 175 | No beam at all (`has_beam=0`) -- just a random gradient + noise, simulating an empty/ambient frame. |

Override any of these via `python3 main.py generate --normal N --tilted N
--noisy N --background N`.

## How each category is rendered

All rendering starts from the general rotated 2D Gaussian:

```
I(x,y) = offset + amplitude * exp(-(a*dx^2 + 2*b*dx*dy + c*dy^2))
```

where `a, b, c` are the standard rotated-Gaussian coefficients derived from
`sigma_x, sigma_y, theta` (see `synthetic/generator.py:gaussian_2d`).

- **normal**: `theta=0`, single sigma value shared by x/y, amplitude
  0.7-1.0, light Gaussian noise (sigma 0.005-0.02).
- **tilted**: two independent sigma values drawn from
  `[MIN_SIGMA, MAX_SIGMA]` (forced to differ by >=10px), `theta` uniform in
  `[10, 170]` degrees.
- **noisy**: similar to normal/tilted but with a random background
  gradient (strength 0.05-0.2), heavier Gaussian noise (0.04-0.09), and
  random hot pixels.
- **background**: no Gaussian at all -- just a random linear gradient
  (strength 0.05-0.25) plus Gaussian noise (0.01-0.04). No hot pixels are
  added here (see below).

## Label schema (`labels.csv`)

| Column | Meaning |
|---|---|
| `filename` | Relative path under `dataset/images/`, e.g. `normal/00000_normal.png` |
| `x0`, `y0` | Beam center in pixels |
| `sigma_x`, `sigma_y` | Beam spread in pixels (see the tilted-beam note below) |
| `theta` | Rotation angle in degrees (metadata only -- not a regression target, since the model has no rotation output) |
| `has_beam` | 1 if a beam is present, 0 for `background` frames |
| `category` | One of `normal` / `tilted` / `noisy` / `background` |
| `split` | `train` / `val` / `test` (80/10/10, shuffled with a fixed seed) |

### Why tilted-beam sigmas are axis-aligned, not principal-axis

A rotated ellipse has two natural descriptions: its **principal-axis
widths** (the "true" major/minor sigma, independent of rotation) and its
**axis-aligned projected widths** (how wide it appears along the image's
x and y axes, which depends on both the principal widths and the
rotation angle).

The CNN has no rotation output -- only `(x, y, sigma_x, sigma_y)`. Given
just a rotated blob's image, the principal-axis widths are
**unrecoverable** without also knowing theta (many `(sigma_major,
sigma_minor, theta)` combinations produce the same visible axis-aligned
extent). So `labels.csv` stores the axis-aligned projected widths for the
`tilted` category:

```
sigma_x_label = sqrt(sigma_major^2 * cos(theta)^2 + sigma_minor^2 * sin(theta)^2)
sigma_y_label = sqrt(sigma_major^2 * sin(theta)^2 + sigma_minor^2 * cos(theta)^2)
```

This is exactly what a real rotation-unaware second-moment beam-width
measurement would report, and it's a well-posed target a 4-output model
can actually learn. (This was found and fixed after the first training
run showed the model's tilted-beam sigma predictions didn't match either
the raw principal sigmas -- they were closer to this projected quantity,
confirming the original label definition was ill-posed.)

## Quality validation

`python3 main.py validate` (or `data/validate.py` directly) checks:

- Every file referenced in `labels.csv` exists, is a valid, correctly
  sized (640x480), grayscale PNG.
- Beam-bearing categories (`has_beam=1`) have a peak brightness above
  60/255 -- catches accidentally near-invisible beams.
- Background frames (`has_beam=0`) stay below a peak of 140/255 -- catches
  any accidental beam-like artifact contaminating the "no beam" label.
- No NaN/Inf in any numeric label column.
- Beam centers fall within the frame; sigma values fall within
  `[0.5*MIN_SIGMA, 1.2*MAX_SIGMA]`.

This validation caught a real bug during development: hot pixels were
originally added to ~30% of `background` frames, occasionally saturating
a pixel to 255 -- a false bright spot contradicting the `has_beam=0`
label. Background frames no longer get hot pixels (see
`synthetic/generator.py:make_background_sample`).
